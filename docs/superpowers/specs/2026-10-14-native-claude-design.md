# Native transparent Claude companion

Goal: one native Claude login for Remote Control, persistent per-session inference account selection with included-quota failover, and simple sign-in/account controls without OmniRoute. Defaults remain unchanged until the user quits Zed and the final ownership handoff is verified.

Reuse cliproxy-rs's dashboard, OAuth login, atomic credential files and sole refresh scheduler. Add a small Node HTTPS forward-proxy companion based on the already qualified transport. Claude Messages inference goes directly to Anthropic using the selected current access token; it never enters the translating/shaping executor. Other Claude/account/Remote Control traffic retains native authentication; other hosts use CONNECT tunnels. Only inference authorization and HTTP hop framing change. Native messages, tools, beta headers, cache markers, model, metadata and response bytes remain unchanged.

The companion authenticates to cliproxy management and reads only Claude access tokens from the configured local auth directory. It never refreshes credentials. Management enable/disable state is checked on each selection. Missing/expired credentials and unavailable owner stop visibly. Stable IDs use imported native_route_id or the organization/account identity, not session contents. SQLite affinity has no TTL. Disabled/exhausted/unavailable accounts can fail over; recovered accounts do not reclaim moved sessions. Unknown response outcome is non-retryable; no partial-stream replay. Fresh included quota is mandatory; paid extra use remains blocked.

A small `cliproxy-native` command manages login (existing PKCE/callback flow), account listing/toggles, dashboard access, health, and typed settings. Health reports owner reachability/authentication, proxy readiness, included quota, account state, pins and sanitized cache counters. No model calls for health. A supervisor owns the credential directory lock and starts both processes, renews the scoped leaf certificate, and restarts failures. Secret files and auth files are private; no tokens or management keys in logs or browser URLs.

Qualification uses isolated auth directories and fake upstreams: management listing/toggles, file rotation, no refresh from companion, missing owner/expired credentials, unknown beta/tool/body byte equality, persistent affinity/failover, raw compressed/JSON responses, cancellation and no replay. Use upstream focused OAuth/management tests as well. Stage a credential-free instance first. Real credential migration occurs only after old sessions drain and the original owner stops; current rotated credentials must be returned before rollback. One small real cache/Remote Control proof is required after handoff, not another full-history test. Existing representative MCP-history proof remains transport evidence; management qualification must not repeat large inference requests.
